# 工作流程總覽

> Claude Code 專案開發流程完整指南。所有可用指令、流程圖、使用情境一覽。

---

## 開發 Phase 總覽

```text
┌─────────────────────────────────────────────────────────────────────────────────────┐
│  Phase 0        Phase 1       Phase 2       Phase 3       Phase 4                   │
│  ──────────     ──────────    ──────────    ──────────    ──────────                │
│  需求規劃        設計/準備      開發循環       測試驗證      完成審查                  │
│                                                                                     │
│  /project:plan  /project:     TDD 實作      E2E 測試      /project:done            │
│  → Tickets      design        RED→GREEN→    (強制)        → Multi-Agent            │
│  → PRD 更新     /project:     REFACTOR                    Review                    │
│                 start-dev                                                           │
│                 /project:tdd                                                        │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

### Phase 說明

| Phase | 名稱 | 指令 | 產出 |
| ----- | ---- | ---- | ---- |
| **0** | 需求規劃 | `/project:plan <需求>` | TICKETS.md 更新、PRD 檢查/更新 |
| **1** | 設計/準備 | `/project:design`、`/project:start-dev` | 設計稿（如需要）、開發環境 |
| **2** | 開發循環 | TDD / 實作 | 程式碼、單元測試 |
| **3** | 測試驗證 | E2E 測試 | E2E 測試通過（強制） |
| **4** | 完成審查 | `/project:done` | Multi-Agent Review 報告 |

```text
│        │     │                                                                  │
│        │     └─ 用戶確認 → 更新 PRD → 進入 Phase 2                                │
│        │                                                                        │
│        └─ ❌ 不在 PRD → 詢問是否新增功能                                          │
│              │                                                                  │
│              └─ 用戶確認 → 新增到 PRD → 進入 Phase 2                              │
│                                                                                 │
│  Phase 2: 需求拆解                                                               │
│     ├─ 分析功能範圍                                                              │
│     ├─ 識別前後端需求                                                            │
│     └─ 定義驗收條件                                                              │
│                                                                                 │
│  Phase 3: Ticket 產出                                                            │
│     ├─ 建立 TICKET-XXX                                                          │
│     ├─ 定義 Backend / Frontend 驗收條件                                          │
│     └─ 更新 TICKETS.md                                                          │
│                                                                                 │
```


### /project:done - 完成審查

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│                              /project:done [TICKET-XXX]                         │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  Step 1: 識別 Ticket                                                            │
│     ├─ 從參數讀取 TICKET-XXX                                                    │
│     ├─ 或從 branch 名稱解析                                                     │
│     └─ 或從最近 commit 解析                                                     │
│                                                                                 │
│  Step 2: 執行測試（並行）                                                        │
│     │                                                                           │
│     ├──────────────┬──────────────┬──────────────┐                             │
│     │              │              │              │                             │
│     ▼              ▼              ▼              ▼                             │
│  ┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐                             │
│  │ Unit  │    │  E2E  │    │ Lint  │    │Coverage│                             │
│  │ Test  │    │ Test  │    │ Check │    │ Check │                             │
│  └───────┘    └───────┘    └───────┘    └───────┘                             │
│                                                                                 │
│  Step 3: Multi-Agent Review（並行）                                             │
│     │                                                                           │
│     ├──────────────┬──────────────┬──────────────┐                             │
│     │              │              │              │                             │
│     ▼              ▼              ▼              ▼                             │
│  ┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐                             │
│  │🔒Sec  │    │🧪Test │    │📐Qual │    │📋 PM  │                             │
│  │ Agent │    │ Agent │    │ Agent │    │ Agent │                             │
│  └───────┘    └───────┘    └───────┘    └───────┘                             │
│                                                                                 │
│  Step 4: 結果判定                                                               │
│     │                                                                           │
│     ├─ Security FAIL → 整體 FAIL（最高優先）                                     │
│     ├─ 任一 Agent FAIL → 整體 FAIL                                              │
│     └─ 全部 PASS → APPROVED                                                    │
│                                                                                 │
│  Step 5: 更新 TICKETS.md                                                        │
│     ├─ APPROVED → 標記 Ticket 為 ✅ 完成                                         │
│     └─ FAIL → 保持狀態，輸出問題清單                                             │
│                                                                                 │
│  輸出:                                                                          │
│     - Final Review Report                                                       │
│     - TICKETS.md 更新                                                           │
│     - PASS / FAIL 結果                                                          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

```text
│     │  │                     │                               │                 │
```

```text

│                                                                                 │
│  輸出:                                                                          │
│     - 修復程式碼                                                                │
```

## 情境指南

### 情境 1: 新功能開發（完整流程）

```text
需求: "實作使用者認證功能"

1. /project:plan 實作使用者認證功能
   → 產出 TICKET-001 ~ TICKET-003
   → 更新 PRD（如需要）
   → 產出設計稿（如有 UI）

2. /project:start-dev TICKET-001
   → 多 Agent 協作開發
   → 自動 Review 循環

3. /project:done
   → 確認全部通過
   → 更新 TICKETS.md
```

### 情境 2: Bug 修復（快速流程）

```text
問題: "登入後無限重導向"

1. /project:fix 登入後無限重導向問題
   → 分析問題
   → TDD 修復
   → 驗證修復

2. /project:done
   → 確認測試通過
   → Review 確認
```

### 情境 3: 純後端開發

```text
需求: "新增 API endpoint"

1. /project:plan 新增用戶資料 API
   → 產出 Backend 類型 Ticket（無設計稿）

2. /project:tdd TICKET-XXX
   → TDD 開發
   → 不需要設計稿

3. /project:done
   → Review（跳過 Design Review）
```

### 情境 4: 從 Figma 設計開發

```text
設計: Figma 設計稿已完成

1. /project:sync-design-system https://figma.com/design/xxx
   → 同步 Design Tokens
   → 產出元件設計稿
   → 比對差異報告

2. /project:start-dev TICKET-XXX
   → 依照設計稿開發
```

## 指令快速參考

### 核心指令

| 指令 | 說明 | 產出 |
| ---- | ---- | ---- |
| `/project:plan <需求>` | 需求規劃 | Tickets、PRD 更新、設計稿 |
| `/project:start-dev TICKET-XXX` | 多 Agent 開發 | 程式碼、Review Report |
| `/project:tdd TICKET-XXX` | TDD 開發 | 程式碼、測試 |
| `/project:done` | 完成審查 | Final Report、TICKETS 更新 |

### 輔助指令

| 指令 | 說明 |
| ---- | ---- |
| `/project:fix <問題>` | 快速修復 Bug |
| `/project:refactor <目標>` | 程式碼重構 |
| `/project:review` | 單獨執行 Review |
| `/project:test` | 執行測試 |
| `/project:test-e2e` | 執行 E2E 測試 |

### 設計指令

| 指令 | 說明 |
| ---- | ---- |
| `/project:design <元件>` | 設計單一元件 |
| `/project:design-system` | 規劃設計系統 |
| `/project:sync-design-system <URL>` | 同步 Figma 設計 |
