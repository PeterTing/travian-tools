## 1. 產品定位

一套給 Travian: Legends 玩家與聯盟用的「全能工具箱 + 知識庫 + 個人／聯盟管理」網站，手機和電腦都要好用。

- **個人：** 多帳號、多世界的村莊管理；涵蓋 Friso（frisovandijk.com/public/travian）與 kirilloid 的全部計算器；開局攻略清單；依村莊角色（hammer / feeder / anvil / cap）排建造順序。
- **聯盟：** 登錄重要目標與敵方攻擊村；第一波攻擊落地後反推攻擊方的競技場（TS）等級，算出每個攻擊村打到每個目標要幾點出兵，排偵查時間判斷真假攻。
- **個人專案：** 不屬於任何公司產品線。程式碼在 `PeterTing/travian-tools`；雲端資源只放在 GCP 專案 `artogo-travian-tools`，不跟其他專案共用服務帳號或資料庫。

## 2. 合規原則（硬性規定）

判斷依據是「技術上會不會留下可被偵測的痕跡」。原則：**工具不主動對 Travian 發出任何請求，也不改動遊戲頁面。**

| 分級 | 做法 | 結論 |
|---|---|---|
| 極低風險 | 使用者按一下擴充，讀取「當下這一頁」已載入的 HTML（`activeTab`） | ✅ P0 |
| 低風險 | 使用者瀏覽到哪頁就被動讀哪頁，不發請求、不插入任何元素 | ⏳ 之後做，必須可關閉 |
| 高風險 | 背景自動開頁、輪流讀村莊、掃地圖或統計頁、自動登入、自動執行任何遊戲動作 | ❌ 永遠不做 |

- 唯一允許連線 Travian 的程式：伺服器每天 04:15 UTC 下載官方公開的 `map.sql`，不帶任何登入資訊；只抓使用者已加入的世界。
- 不儲存任何 Travian 帳號密碼。
- CI 有合規測試：出現瀏覽器自動化、或在 `map.sql` 以外連線 Travian，CI 一律失敗。

## 3. 資料進入方式

三個入口，全部進同一個「解析結果確認」畫面，確認後才存入。

1. **擴充上傳（電腦）：** 只用 `activeTab`，按一下才讀。頁面有 `#servertime`（伺服器 unix 時間）與每筆倒數的剩餘秒數，相加就是抵達時間，誤差 2 秒內。
2. **貼上（手機與電腦）：** 首頁提供「從剪貼簿貼上」按鈕與可長按貼上的大輸入框；按鈕讀不到剪貼簿時退回輸入框（iOS 限制）。
3. **截圖辨識（手機）：** 可一次上傳多張，重疊的部分自動去掉。計算器裡的座標欄位旁邊有相機按鈕。

### 3.1 時間處理

- 擴充上傳：直接用伺服器時間。
- 貼上與截圖：文字裡只有時鐘時間。每個遊戲帳號存一個「遊戲內時間顯示時區」設定（伺服器時間或本地時間），第一次貼上時詢問。確認畫面上的「擷取時間」可以修改，接近午夜時提醒確認日期。
- 存入的一律是換算好的絕對抵達時間，畫面上的倒數都從抵達時間往回算。

### 3.2 重複與更新

- 重貼集結點時，按「來源村、目標村、同一秒抵達」分組。這次貼上有 N 筆、資料庫已有 M 筆時，前 min(N, M) 筆算更新，多出來的才新增。重貼時**永遠不自動刪除**。
- 確認畫面標示「新增 X 筆、更新 Y 筆」。

### 3.3 截圖辨識

- 引擎：RapidOCR（PaddleOCR 小模型的 ONNX 版）自架在 Cloud Run，P0 只用它。P1 再加 Gemini 2.5 Flash（Vertex AI，us-central1）複查不是全部 ok 的截圖。實測 Gemini 單獨使用時有 0.6% 讀錯卻標成 ok，所以不能單獨靠它。
- 實測：18 張桌機截圖，全部欄位 99.3% 正確，時間 100%，座標 98.4%；標成正確卻讀錯的是 0／246。上線前要再收 50 到 100 張手機截圖驗證，樣本由使用者勾選同意後收集（預設關閉）。
- 欄位狀態：
  - **待補**：讀不到，可以先存，之後補。
  - **低信心**：可能讀錯，必須確認才能存入。
- 低信心不能只看 OCR 分數，要加規則檢查，回傳原因代碼（多個原因時，最嚴重的排第一）：`OCR_LOW_SCORE`、`TIME_FORMAT_INVALID`、`COORD_OUT_OF_RANGE`、`COORD_MAP_MISMATCH`、`COUNTDOWN_ARRIVAL_MISMATCH`、`OVERLAP_MISMATCH`、`NUMBER_FORMAT_INVALID`、`RESOURCE_OVER_CAPACITY`、`LAYOUT_AMBIGUOUS`、`DUPLICATE_VALUE`、`TEXT_TOO_SMALL`、`NO_CROSS_CHECK`、`CROP_RECHECK_MISMATCH`；P1 加入 Gemini 複查後再加 `MODEL_UNSURE`、`ENGINE_MISMATCH`、`SINGLE_ENGINE`。`TRUNCATED_AT_EDGE`、`PARSE_ERROR` 搭配「待補」狀態使用。
- `COORD_MAP_MISMATCH`：拿座標去查 `map.sql`，看村名和玩家名對不對得上。對不上只標低信心、不直接判錯，因為地圖每天才更新一次。
- 攻擊方座標不論信心高低，都附上截圖縮圖讓人核對。
- 等待：每張約 2 到 3 秒，進度條最多跑 5 秒，超過就提示「比平常久」（也涵蓋冷啟動）。
- 成本：Gemini 複查每張約 0.0013 美元，Peter 自己用每月約 0.4 美元，一個聯盟約 5 美元。預算警示設在 `artogo-travian-tools`，每月 20 美元，用到 50%、90%、100% 時各通知一次；另外設每分鐘請求數上限當硬上限。不保留常駐主機，冷啟動交給「比平常久」的提示處理。

## 4. 功能範圍與分期

### P0：資料進得來、基本計算正確（約 14 到 17 人天，截圖辨識另計）

| # | 功能 | 驗收標準 |
|---|---|---|
| P0-1 | 後端瘦身與合規（PR #1） | 自動化、自動登入、密碼欄位與資料全部移除；合規測試在 CI 上跑；新建的資料庫跟程式裡的資料表定義完全一致 |
| P0-2 | 帳號、世界切換與村莊列表 | 一個使用者可以有多個遊戲帳號，資料按帳號和世界分開存 |
| P0-3 | 共用解析器 | 集結點：搶奪不會同時算成出兵和來襲，駐軍不會被當成增援；支援多村總覽；擴充、貼上、截圖共用同一套解析器 |
| P0-4 | 擴充重寫 | 只用 `activeTab`，沒有背景程式，不改動頁面 |
| P0-5 | 貼上流程與「解析結果確認」畫面 | 符合線框稿 v0.6；三種入口共用同一個確認元件 |
| P0-6 | 最簡單的來襲列表 | 依抵達時間排序、顯示倒數、標出待補；可以點進去補座標 |
| P0-7 | 截圖辨識：集結點與座標欄位 | 符合 3.3；悄悄讀錯（沒被規則攔下）的比例要用手機樣本實測 |
| P0-8 | `map.sql` 匯入 | 名字含單引號的村莊不會漏；部族與首都讀對欄位；可手動上傳 `.sql`／`.gz` |
| P0-9 | 計算器 | 搬入 travian-guide 已有測試的 8 個計算器（建造順序用 guide 的版本）；競技場加速全專案統一成正確公式（見 5） |
| P0-10 | 開局攻略清單 | 內容取自 Peter 的 Excel（T4.6，4P 農開、3P 兵開、任務、派對與文明點時間），可以逐項勾選 |
| P0-11 | RWD 外框 | 手機優先；導覽列不留 AI、執行、知識庫的入口；戰鬥模擬先隱藏 |

### P1：聯盟防守（約 15 到 20 人天）

- 反推 TS 等級（用第一波攻擊的距離、兵種和實際飛行時間）
- 戰報解析（攻擊、防守、偵查）。需要樣本頁，排在 P1 後段
- 村莊總覽與戰報的截圖辨識；加上 Gemini 複查（約 2 到 3 天）
- 聯盟群組與權限；登錄重要目標與敵方攻擊村
- 真假攻判斷與偵查時間表：算每個攻擊村打每個目標的出兵時間，排偵查去看兵在不在家
- 戰鬥模擬器重寫；修正鐵匠鋪公式
- 偵查找田照 Friso 的規則重做
- 知識庫：以 travian-guide 的內容為主體，舊知識庫逐條跟 kirilloid 校對後才併入

### P2：進階（P1 完成後再估）

- 依村莊角色排建造順序的最佳化器（資源田與建築）
- Discord 通知
- 成員統計
- 攻擊與神器計畫
- 被動讀取當下頁面（合規分級的「低風險」，可關閉）

### 不做

- 任何自動執行遊戲動作或背景抓資料的功能（見 2）
- AI 策略顧問（v1 的功能已移除）
- v1 自己編的村莊建造、偵查找田、假兵計算器（偵查找田在 P1 照 Friso 重做）

## 5. 計算正確性

- 數值以 travian-guide 的資料檔與測試為準，並跟 kirilloid 核對；v1 PRD 第 7 章的公式已確認有誤，不再參考。
- **競技場（TS）加速：** 只有超過 20 格的那段距離會加速，每級加 20%，20 級是 5 倍；另外乘上靴子、神器、軍旗等加成。
- 每個計算器都要有對照 kirilloid 或 Friso 輸出的測試案例。

## 6. 技術架構

- 前端：React + Vite + Tailwind（pnpm monorepo），中英雙語
- 後端：FastAPI + MySQL
- 部署：Cloud Run（GCP 專案 `artogo-travian-tools`），不保留常駐主機
- 擴充：Chrome Manifest V3，只申請 `activeTab`

### 資料模型（摘要）

User → GameAccount（世界、部族、時間顯示時區）→ Village（座標、角色、建築、資源田）

Alliance → Member、Target、EnemyAttackerVillage、IncomingAttack（來源、目標、抵達時間、狀態、上次偵查時間）、ScoutPlan
